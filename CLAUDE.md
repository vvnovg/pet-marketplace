## Project Overview

This is a Spring Boot 4.x backend for a pet marketplace. It connects sellers (breeders, shelters, private individuals) with buyers, providing listing publication, search, bookings, internal messaging, reviews and moderation tools.

## Common Commands

All Gradle commands require JDK 26 and Gradle 9. The system defaults are already OpenJDK 26 and Gradle 9.6.1 on PATH, so no `JAVA_HOME` override is needed and commands use the system `gradle` directly (the bundled `./gradlew` wrapper targets Gradle 8.14, which cannot run on JDK 26). If `java` is not on PATH, set it explicitly:

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk/libexec/openjdk.jdk/Contents/Home
```

Build the project:

```bash
gradle build -x test
```

Run all tests (requires Docker for Testcontainers):

```bash
gradle test
```

Run a single test class:

```bash
gradle test --tests "com.petmarketplace.application.auth.controller.AuthControllerTest"
```

Run the application locally:

```bash
docker-compose up -d
gradle bootRun
```

The API is available at `http://localhost:8080/api/v1` and Swagger UI at `http://localhost:8080/api/v1/swagger-ui.html`.

## Architecture

The application follows a layered architecture under `src/main/java/com/petmarketplace`:

- `application` — REST controllers, DTOs (Java records), MapStruct mappers and services. Organized by domain module: `auth`, `user`, `category`, `listing`, `booking`, `message`, `review`, `favorite`, `subscription`, `admin`.
- `domain` — JPA entities extending `BaseEntity` or `AuditEntity`, enums and Spring Data JPA repositories.
- `infrastructure` — cross-cutting concerns: Spring Security/JWT, file storage (local or MinIO), email sending, localized name resolution.
- `config` — Spring configuration beans (cache, async, OpenAPI, JPA auditing).
- `exception` — `GlobalExceptionHandler` returning a consistent `ApiError` JSON structure.

### Base Entities

- `BaseEntity` — provides a UUID primary key generated by Hibernate, plus `equals`/`hashCode` based on id.
- `AuditEntity` extends `BaseEntity` and adds `createdAt`/`updatedAt` timestamps via JPA auditing.

Use `AuditEntity` when the database table has `created_at` and `updated_at` columns; use `BaseEntity` when only `created_at` exists (e.g. `Message`, `Category`, `Breed`, `Favorite`, `Subscription`).

### Domain Modules

- **auth** — JWT-based authentication and authorization. Access tokens expire in 15 minutes; refresh tokens are stored in Redis with a 7-day TTL and rotated on use.
- **user** — user accounts and profiles. A `Profile` is created automatically when a user registers. Profiles keep a computed `rating` and `totalReviews` that are recalculated when reviews are approved.
- **category** — hierarchical categories (species) and breeds with Russian/English localized names and Redis caching.
- **listing** — pet sale listings with statuses `DRAFT`, `PENDING_MODERATION`, `ACTIVE`, `RESERVED`, `SOLD`, `ARCHIVED`, `REJECTED`. Search uses Spring Data JPA Specifications with filters for category, breed, city, price, gender and age.
- **booking** — purchase requests with status transitions `PENDING → CONFIRMED → COMPLETED` or `CANCELLED`. Confirming a booking sets the listing to `RESERVED`; completing sets it to `SOLD`; cancelling from `CONFIRMED` returns it to `ACTIVE`.
- **message** — one-to-one chat between users, with optional attachments and read receipts.
- **review** — buyer reviews of sellers after a completed booking. Reviews start as `PENDING` and require moderator approval before affecting the seller's rating.
- **favorite / subscription** — saved listings and saved search filters stored as JSONB.
- **admin** — user/role management, listing/review moderation and platform statistics.

## Security

Spring Security is configured in `infrastructure/security/SecurityConfig`:

- Stateless JWT sessions.
- Public endpoints: `/auth/**`, `/categories/**`, `GET /listings/**`, `GET /users/{id}/**`, Swagger, `/actuator/health`.
- `/admin/**` requires `ADMIN` or `MODERATOR` role.
- All other endpoints require authentication.

JWT properties come from `security.jwt.*` in `application.yml` or from environment variables `JWT_SECRET`, `JWT_ACCESS_EXPIRATION_MINUTES`, `JWT_REFRESH_EXPIRATION_DAYS`. The secret must be at least 256 bits for HS256.

## Database and Migrations

- PostgreSQL 16 with schema managed by Liquibase.
- Master changelog: `src/main/resources/db/changelog/db.changelog-master.yaml`.
- Initial schema and seed data (categories and breeds) are in `changelogs/001-init-schema.yaml`.
- `hibernate.ddl-auto` is `none` — all schema changes must go through Liquibase.

## File Storage

`FileStorageService` is the abstraction. The active implementation is selected by `storage.provider` (`local` or `minio`). Local storage writes to `storage.local.base-path` (default `./uploads`). MinIO settings are in `storage.minio.*`.

## Email and Notifications

Emails are sent asynchronously using a dedicated thread pool. Templates live in `src/main/resources/templates/mail/`. When `mail.enabled` is `false` (default), the `EmailSenderStub` logs messages instead of sending them. Mailpit is available in Docker Compose for local testing on port `1025` (SMTP) and `8025` (web UI).

## Configuration

Active profile is `dev` by default. Profile-specific settings are merged from `application.yml` sections. Important properties:

- `server.servlet.context-path: /api/v1` — all endpoints are prefixed with `/api/v1`.
- `spring.jackson.default-property-inclusion: non_null` — null fields are not serialized.
- Timestamps are stored and serialized in UTC.

## Testing

Integration tests extend `IntegrationTestBase`, which starts Testcontainers for PostgreSQL and Redis and binds them via `@DynamicPropertySource`. The `test` profile uses a dedicated JWT secret and a random server port. Tests are skipped automatically when Docker is unavailable (`@Testcontainers(disabledWithoutDocker = true)`).

## Code Conventions

- Java 26 with Lombok and MapStruct.
- MapStruct uses the Spring component model (`-Amapstruct.defaultComponentModel=spring`).
- Java compile uses `-parameters` so Spring cache keys can reference method argument names.
- Business errors throw `BusinessException` (maps to HTTP 409) or `ValidationException` (HTTP 400). Not-found cases throw `ResourceNotFoundException` (HTTP 404).
