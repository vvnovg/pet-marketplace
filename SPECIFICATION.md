# Техническая спецификация: Маркетплейс продажи животных

## 1. Общее описание проекта

### 1.1. Цель
Разработать backend-приложение на базе Spring Boot для маркетплейса по продаже домашних животных. Система должна объединять продавцов (заводчиков, приюты, частных лиц) и покупателей, обеспечивая удобный поиск, публикацию объявлений, бронирование, коммуникацию между сторонами и оформление сделок.

### 1.2. Целевая аудитория
- Продавцы животных (заводчики, питомники, приюты, частные лица).
- Покупатели, ищущие домашних питомцев.
- Администраторы платформы (модерация контента, управление пользователями).

### 1.3. Ограничения
- MVP-версия фокусируется на backend и REST API.
- Web-интерфейс и мобильные приложения выходят за рамки MVP, но API проектируется с учётом их последующей интеграции.
- География работы: страны СНГ с поддержкой русского и английского языков.

## 3. Архитектура системы

Приложение построено по принципу многослойной архитектуры (Layered Architecture) с разделением на модули.

### 3.1. Основные слои
- **Controller layer** — REST-контроллеры, валидация входных DTO, обработка исключений.
- **Service layer** — бизнес-логика, транзакционность.
- **Repository layer** — доступ к данным через Spring Data JPA.
- **Domain layer** — сущности, value objects, enums.
- **Infrastructure layer** — конфигурации, безопасность, уведомления, интеграции.

### 3.2. Модули
1. **auth** — регистрация, аутентификация, восстановление пароля.
2. **users** — профили пользователей, роли, рейтинги.
3. **listings** — объявления о продаже животных.
4. **categories** — категории видов/пород животных.
5. **bookings** — бронирование и сделки.
6. **messages** — переписка между пользователями.
7. **reviews** — отзывы и рейтинги.
8. **admin** — модерация, управление пользователями и объявлениями.
9. **notifications** — уведомления (email/push).

### 3.3. Схема развёртывания

## 4. Функциональные требования

### 4.1. Управление пользователями

#### FR-1. Регистрация и аутентификация
- Регистрация по email/телефону с подтверждением.
- Аутентификация через JWT (access + refresh tokens).
- Восстановление пароля через email.
- Поддержка OAuth2 (Google, Apple ID) — на втором этапе.

#### FR-2. Роли пользователей
- `BUYER` — покупатель.
- `SELLER` — продавец.
- `ADMIN` — администратор.
- `MODERATOR` — модератор.
- Роль `SELLER` присваивается после верификации профиля.

#### FR-3. Профиль пользователя
- Просмотр и редактирование личных данных.
- Загрузка аватара.
- Указание местоположения (страна, город, адрес).
- История объявлений, сделок и отзывов.
- Рейтинг пользователя на основе отзывов.

### 4.2. Управление объявлениями

#### FR-4. Создание объявления
Продавец может создать объявление с указанием:
- категории (вид животного);
- породы;
- пола;
- возраста (дата рождения);
- окраса;
- размера;
- состояния здоровья, вакцинаций, наличия документов;
- цены;
- местоположения;
- описания;
- до 10 фотографий;
- контактов.

#### FR-5. Модерация объявлений
- Новые объявления проходят премодерацию.
- Модератор может одобрить, отклонить или запросить исправления.
- Автоматическая проверка на запрещённый контент.

#### FR-6. Поиск и фильтрация
- Поиск по виду, породе, городу, цене, возрасту, полу.
- Сортировка: по дате, цене, популярности, рейтингу продавца.
- Пагинация результатов.
- Сохранение поисковых запросов.

#### FR-7. Статусы объявлений
- `DRAFT` — черновик.
- `PENDING_MODERATION` — на модерации.
- `ACTIVE` — активно.
- `SOLD` — продано.
- `ARCHIVED` — в архиве.
- `REJECTED` — отклонено.

### 4.3. Бронирование и сделки

#### FR-8. Бронирование
- Покупатель может отправить заявку на бронирование животного.
- Продавец подтверждает или отклоняет заявку.
- При бронировании животное помечается статусом `RESERVED`.

#### FR-9. Статусы бронирования
- `PENDING` — ожидает подтверждения.
- `CONFIRMED` — подтверждено.
- `CANCELLED` — отменено.
- `COMPLETED` — сделка завершена.

#### FR-10. История сделок
- Хранение истории всех бронирований и сделок.
- Генерация карточки сделки с основными данными.

### 4.4. Коммуникации

#### FR-11. Внутренний чат
- Обмен сообщениями между покупателем и продавцом.
- Прикрепление фотографий к сообщениям.
- Статус доставки (отправлено / доставлено / прочитано).
- Уведомления о новых сообщениях.

### 4.5. Отзывы и рейтинги

#### FR-12. Отзывы
- Покупатель может оставить отзыв о продавце после завершённой сделки.
- Оценка по 5-балльной шкале.
- Текстовый комментарий.
- Модерация отзывов.

#### FR-13. Рейтинг
- Автоматический пересчёт рейтинга пользователя.
- Отображение среднего рейтинга в профиле и карточках объявлений.

### 4.6. Избранное и подписки

#### FR-14. Избранные объявления
- Добавление объявлений в избранное.
- Управление списком избранного.

#### FR-15. Подписки
- Подписка на новые объявления по заданным критериям поиска.
- Email-уведомления о появлении подходящих объявлений.

### 4.7. Уведомления

#### FR-16. Email-уведомления
- Подтверждение регистрации.
- Восстановление пароля.
- Новое сообщение.
- Изменение статуса объявления/бронирования.
- Новые подходящие объявления по подписке.

### 4.8. Администрирование

#### FR-17. Панель администратора
- Управление пользователями (блокировка, разблокировка, смена ролей).
- Модерация объявлений и отзывов.
- Просмотр статистики платформы.
- Управление категориями и породами.

## 5. Нефункциональные требования

### 5.1. Производительность
- Время ответа API для 95% запросов — не более 300 мс.
- Поддержка одновременной работы не менее 1000 пользователей.
- Поиск по объявлениям — не более 1 секунды.

### 5.2. Надёжность
- Доступность системы — 99.9%.
- Регулярное резервное копирование БД.
- Graceful degradation при недоступности вспомогательных сервисов.

### 5.3. Безопасность
- Хранение паролей с использованием BCrypt.
- Защита от SQL-инъекций, XSS, CSRF.
- Rate limiting на критичных endpoint'ах (авторизация, регистрация).
- Валидация загружаемых файлов (тип, размер).
- JWT с коротким сроком жизни access token (15 минут) и refresh token (7 дней).
- HTTPS-only в production.
- Логирование действий администраторов.

### 5.4. Масштабируемость
- Stateless-архитектура для горизонтального масштабирования.
- Возможность вынесения тяжёлых операций в отдельные сервисы.

### 5.5. Локализация
- Поддержка русского и английского языков.
- Хранение локализуемых полей в БД с указанием языка.

### 5.6. Мониторинг
- Интеграция с actuator и Prometheus.
- Логирование через SLF4J + Logback.
- Сбор метрик производительности.

## 7. REST API

### 7.1. Аутентификация
- `POST /api/v1/auth/register` — регистрация.
- `POST /api/v1/auth/login` — вход.
- `POST /api/v1/auth/refresh` — обновление токенов.
- `POST /api/v1/auth/logout` — выход.
- `POST /api/v1/auth/forgot-password` — запрос восстановления пароля.
- `POST /api/v1/auth/reset-password` — сброс пароля.
- `POST /api/v1/auth/verify-email` — подтверждение email.

### 7.2. Пользователи
- `GET /api/v1/users/me` — текущий пользователь.
- `PUT /api/v1/users/me` — обновление профиля.
- `POST /api/v1/users/me/avatar` — загрузка аватара.
- `GET /api/v1/users/{id}` — публичный профиль.
- `GET /api/v1/users/{id}/listings` — объявления пользователя.
- `GET /api/v1/users/{id}/reviews` — отзывы о пользователе.

### 7.3. Объявления
- `GET /api/v1/listings` — список объявлений (с фильтрами).
- `GET /api/v1/listings/{id}` — детали объявления.
- `POST /api/v1/listings` — создание объявления.
- `PUT /api/v1/listings/{id}` — редактирование.
- `DELETE /api/v1/listings/{id}` — удаление.
- `POST /api/v1/listings/{id}/images` — загрузка фото.
- `DELETE /api/v1/listings/{id}/images/{imageId}` — удаление фото.
- `POST /api/v1/listings/{id}/favorite` — добавить в избранное.
- `DELETE /api/v1/listings/{id}/favorite` — удалить из избранного.
- `POST /api/v1/listings/{id}/book` — подать заявку на бронирование.

### 7.4. Категории
- `GET /api/v1/categories` — список категорий.
- `GET /api/v1/categories/{id}/breeds` — породы категории.

### 7.5. Бронирования
- `GET /api/v1/bookings` — список бронирований текущего пользователя.
- `GET /api/v1/bookings/{id}` — детали бронирования.
- `PUT /api/v1/bookings/{id}/confirm` — подтвердить.
- `PUT /api/v1/bookings/{id}/cancel` — отменить.
- `PUT /api/v1/bookings/{id}/complete` — завершить.

### 7.6. Сообщения
- `GET /api/v1/messages` — список диалогов.
- `GET /api/v1/messages/{userId}` — переписка с пользователем.
- `POST /api/v1/messages` — отправить сообщение.
- `PUT /api/v1/messages/{id}/read` — отметить прочитанным.

### 7.7. Отзывы
- `POST /api/v1/reviews` — оставить отзыв.
- `GET /api/v1/reviews/{userId}` — отзывы о пользователе.

### 7.8. Избранное
- `GET /api/v1/favorites` — список избранного.

### 7.9. Подписки
- `GET /api/v1/subscriptions` — список подписок.
- `POST /api/v1/subscriptions` — создать подписку.
- `DELETE /api/v1/subscriptions/{id}` — удалить подписку.

### 7.10. Администрирование
- `GET /api/v1/admin/users` — список пользователей.
- `PUT /api/v1/admin/users/{id}/status` — изменить статус.
- `PUT /api/v1/admin/users/{id}/role` — изменить роль.
- `GET /api/v1/admin/listings/pending` — объявления на модерации.
- `PUT /api/v1/admin/listings/{id}/moderate` — модерация объявления.
- `GET /api/v1/admin/reviews/pending` — отзывы на модерации.
- `PUT /api/v1/admin/reviews/{id}/moderate` — модерация отзыва.
- `GET /api/v1/admin/statistics` — статистика.

## 8. Безопасность

### 8.1. Аутентификация
- JWT access token сроком 15 минут.
- JWT refresh token сроком 7 дней, хранится в Redis с возможностью отзыва.
- Refresh token ротация при каждом обновлении.

### 8.2. Авторизация
- Доступ к endpoint'ам на основе ролей и прав владения ресурсом.
- Продавец может редактировать/удалять только свои объявления.
- Администратор/модератор имеют расширенные права.

### 8.3. Защита данных
- Валидация всех входных данных.
- Ограничение размера загружаемых файлов (макс. 5 МБ на фото).
- Хранение медиа в отдельном хранилище (S3-compatible, например MinIO для dev).
- Маскирование чувствительных данных в логах.

### 8.4. Rate Limiting
- 5 попыток входа в минуту.
- 3 попытки восстановления пароля в час.
- 10 запросов на создание объявления в час для новых пользователей.

## 10. Критерии приёмки

- Пользователь может зарегистрироваться, подтвердить email и войти.
- Продавец может создать объявление с фотографиями.
- Объявление проходит модерацию перед публикацией.
- Покупатель может искать объявления по фильтрам.
- Покупатель может отправить заявку на бронирование.
- Продавец может подтвердить/отклонить заявку.
- Пользователи могут обмениваться сообщениями.
- После завершения сделки покупатель может оставить отзыв.
- Администратор может модерировать контент и управлять пользователями.
- API покрыто тестами с покрытием не менее 70%.

## 11. Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Сложности с модерацией фото | Средняя | Среднее | Ручная модерация + постепенное внедрение автоматических проверок |
| Нагрузка на поиск | Средняя | Высокое | Индексы, кеширование, Elasticsearch на этапе масштабирования |
| Мошенничество | Высокая | Высокое | Верификация продавцов, отзывы, жалобы, модерация |
| Зависимость от внешних сервисов | Низкая | Среднее | Graceful degradation, резервные провайдеры |

## 12. Приложения

### 12.1. Глоссарий
- **MVP** — Minimum Viable Product, минимально жизнеспособный продукт.
- **JWT** — JSON Web Token.
- **CRUD** — Create, Read, Update, Delete.
- **CHPU** — Человеко-понятный URL (slug).

### 12.2. Соглашения
- Код пишется на Java 26 с использованием Lombok.
- Все API endpoint'ы начинаются с `/api/v1/`.
- Временные метки хранятся в UTC, отображаются в локальном часовом поясе клиента.
- Все денежные суммы хранятся в минимальных единицах валюты (копейки/центы) или DECIMAL с точностью 2 знака.
